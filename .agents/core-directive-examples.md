# Core Directive Examples

모호성·권한·범위 판단이 필요할 때만 이 문서를 읽는다.

## 1. 대상 모호성

### 예시 1: 파일과 함수가 함께 지칭됨

사용자: “`A.cpp`를 지워줘.”

확인: “파일 전체 삭제인가요, 특정 함수 삭제인가요? 1번 파일 전체, 2번 특정 함수, 3번 삭제 없이 검토 중 하나를 선택해 주세요.”

### 예시 2: 지시 대상이 여러 개임

사용자: “이 문서를 수정해.”

확인: “현재 문서와 직전에 다룬 문서 중 어느 파일인가요? 정확한 경로를 지정해 주세요.”

## 2. 승인 해석

| 문장 | 판정 |
|---|---|
| “`A.md`에 권고안을 작성해.” | `A.md` 작성 승인 |
| “`A.md`를 수정해도 될까?” | 질문이며 승인 아님 |
| “사용자가 ‘수정해’라고 말하면 어떻게 돼?” | 인용이며 승인 아님 |
| “`A.md`를 검토해줘.” | 읽기 전용 검토 승인 |
| “방금 검토한 두 보고서를 하나로 정리해.” | 대화 맥락에서 대상이 하나로 확정되면 작성 승인 |

## 3. 범위 잠금

사용자가 `A.h`만 수정 요청했는데 `A.cpp`도 필수로 바뀌어야 하는 경우:

1. `A.h`와 `A.cpp`가 함께 바뀌어야 하는 이유를 설명한다.
2. 변경 예정 파일 목록과 검증 방법을 제시한다.
3. 관련 파일 집합에 대한 범위 승인을 받은 뒤 함께 수정한다.

사용자가 처음부터 “선언과 구현을 함께 수정해”라고 요청해 두 파일이 명확히 승인된 경우에는 내부 단계마다 다시 묻지 않는다.

## 4. 읽기와 쓰기 구분

사용자가 “`A.md`를 검토해줘”라고 요청한 경우 파일 열람·검색·분석은 수행할 수 있지만, 수정본 저장·HTML 생성·CHANGELOG 갱신은 별도 승인 대상이다.
